### The plan digest a sink records is stable across releases

A sink's contract records a digest of the plan that wrote it, and a refresh resumes from the sink only when the plan's digest is the same. The digest used to be the sha256 of the plan's text, which lists every function the writer knows, so each release that added or dropped a function changed it and the first refresh after an upgrade rewrote every sink in full. The digest is now the sha256 of the plan with that list left out and each function reference replaced by the function's name: the same plan gives the same digest in 0.7.0 and 0.8.0, which the critique's run showed ([#1485](https://github.com/AlexanderNenninger/substrait-lean/issues/1485), finding 24). This release recomputes sinks once, as it changes the digest; the ODCS and OpenLineage exports record the new digest too. A release that changes the canonical form, or what a plan means, says so in its changelog.
