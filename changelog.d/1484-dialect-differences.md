Breaking for raw SQL: under the default `semantics="reference"`, `CAST(x AS <integer>)` of a double or a decimal in DuckDB SQL is refused by the lift ([D54](docs/decisions.md#d54-the-lift-refines-the-dialect), #1484), where it truncated and DuckDB rounds (half to even for a double, half away from zero for a decimal). Write `CAST(round(x) AS BIGINT)`, `CAST(floor(x) AS BIGINT)` or `CAST(ceil(x) AS BIGINT)` for a double, which mean the same on both, and `CAST(round(CAST(d AS DOUBLE)) AS BIGINT)` for a decimal; the error names them. The refusal ends when #322 gives the model a rounding cast. The Ibis frontend's cast still truncates (R9).

`Report.dialect_differences` lists where the reference reads a DuckDB SQL text differently from DuckDB on a value and the lift does not refuse it: `corr` of one pair or of a side whose values are all equal (NULL here, NaN on DuckDB). Each entry has the construct, where it is, both readings, an example and the spellings that mean the same. `str(report)` prints them as notes, `to_json` carries them, and the verdict is unchanged. The list is empty under `semantics="duckdb"` and for an Ibis transformation.
