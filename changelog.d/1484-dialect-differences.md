`Report.dialect_differences` lists where the reference reads a DuckDB SQL text differently from DuckDB on a value ([D54](docs/decisions.md#d54-the-lift-refines-the-dialect), #1484): `CAST(double AS integer)` (truncates here, rounds half to even on DuckDB), `CAST(decimal AS integer)` (truncates here, rounds half away from zero) and `corr` of one pair or a constant side (NULL here, NaN on DuckDB). Each entry has the construct, where it is (the query or a condition), both readings, an example and the spellings that mean the same under both semantics (`CAST(round(x) AS BIGINT)`, `floor`, `ceil`). `str(report)` prints them as notes, `to_json` carries them, and the verdict is unchanged. The list is empty under `semantics="duckdb"` and for an Ibis transformation.
