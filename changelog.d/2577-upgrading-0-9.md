### Migration notes for 0.9.0, and old spellings that name their replacement

[docs/upgrading.md](docs/upgrading.md), on the docs site beside the stability page, gives each breaking change of 0.9.0 a migration note with an example, and names the engine fact or upstream record behind each of its soundness fixes ([#2577](https://github.com/AlexanderNenninger/substrait-lean/issues/2577)). More old spellings say what replaced them: a renamed name of `sverify`, `sverify.types`, `sverify.errors`, `sverify.odcs` or `sverify.io` read as an attribute (`sverify.types.Observation` says `sverify.types.Lenses`; `from sverify.types import Observation` still fails with Python's own `ImportError`), `--output-format` and `--json` (`--format`), and `sv.sql(as_=)` (`name=`). A sink class that sets 0.8's `_keeps_retired` is refused with `keeps_retired = True`, and a build with `SVERIFY_PREBUILT_CHECK` set stops naming `SVERIFY_PREBUILT_CHECKER`; both were ignored without a word. `tests/test_breaking_0_9.py` runs each 0.8 spelling.
