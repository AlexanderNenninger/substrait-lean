### Breaking: the default observation reads one zero and list elements as a multiset

Where `ensures` names no observation (`Report.observation`, a sink's `reproducible`), `-0.0` now equals `0.0` and every NaN equals every other (`zeros="canon"`), and the order of a list's elements is not observed (`elements="multiset"`), as the order of rows is not ([#1285](https://github.com/AlexanderNenninger/substrait-lean/issues/1285), [the default observation](docs/core-semantics.md#the-default-observation)). Engines then run a plan as written where only the sign of a zero differs, with no zero-sign shim (`DuckDB`'s `round(-0.4)` may return `-0.0`); a contract that observes the signs (`sv.equivalent(floats="plan")` names zeros exact) keeps the shim. The order of elements counts with an `ORDER BY` inside the aggregate or `elements="sequence"`. `Report.observation` and its JSON (`equivalence`) show the new levels, so a report stored before reads as the new default where it carried none. A contract that names `sv.equivalent(...)` keeps every component it does not name exact, as before. The checker reads `elements="multiset"` for `Report.deterministic` in a follow-up: until then an unordered `collect` or `string_agg` still reports a tie place.
